# N-Island 2.5.0-preview.1 — source preview, NOT a stable binary release

Base: `33ede499b1b3bc0903ba261b81a011b4ab116b1a` (v2.4.4).
This branch deliberately does not change the latest stable release. No Windows binaries or checksums are published from an untested build.

## Implemented

* 16 local, no-network widgets: counter, scoreboard, habit, packing checklist, intervals, eye break, tip/split bill, discount, unit converter, percentages, random number, reaction, memory pairs, palette, pocket-budget tally, day progress. `/widget <key>`; catalog `/widgets`.
* 11 two-player games via `/games`: tic-tac-toe, connect four, 4×4 reversi, Nim, take-21, race-to-30, number guessing, Pig, rock/paper/scissors, 4×4 battleship (three random single-cell ships), 2×2 dots/boxes. **No chess.**
* Real invite routing: `https://t.me/<bot>?start=game_<96-bit random id>`. One opponent, 24-hour expiry, max 100 sessions / 12 active creations per player. Private chats only. State stored in `%APPDATA%\NIsland\friend-games.json` (or `NISLAND_DATA`). The PC and N-Island must remain running; Telegram long polling needs no incoming ports or router changes. No external game server is claimed.
* Separate game handler before owner-only routing. Players cannot invoke PC commands through game operations. Participant, message, turn and revision checks; replay/occupied-cell protection; private RPS choices and hidden enemy ships; atomic state-file replacement. Disable via the bot's “Game server for friends” setting. Do not run two bot pollers with the same token.
* Player: capability-aware seek/shuffle/repeat/rate controls, source switch, source and approximate-time display, rate-aware progress and synced-lyrics timing.
* Paginated widget catalog (six items/page), reusable refresh buttons without unsupported page navigation, theme-aware button states, timestamp safe-area padding, reduced-motion CSS, widget captions.
* Production Bot API 10.4 constraints: private widget messages only, no widget forwarding or inline widget results. Old share callbacks explain the restriction. Shared-widget queries cannot run PC actions.
* UTF-8 query/state validation and HTML/zlib budgets, bounded widget-answer deadline, no timer-driven privileged retry, safe per-message action gates. Fixed duplicate `события` key that could fail static initialization.
* Russian, English, Ukrainian supported; old translation entries retained, explicit new strings added. Widget template translation only touches known UI literals, not user text/command ids.

## Reproducible checks

```powershell
dotnet build NIsland.csproj -c Release
dotnet run --project tools/WidgetAudit -- . widget-audit
dotnet run --project tools/GameAudit -- widget-audit
```

Portable checks also run on .NET 8/Linux. Windows-targeted cross-build:
`dotnet build -c Release -p:EnableWindowsTargeting=true`.

`WidgetAudit` checks profile budgets (UTF-8 HTML ≤32768, zlib ≤4096, state ≤1024, query ≤64), translation coverage, duplicate dictionary keys, templates and 450 pet combinations. `GameAudit` compiles the **actual** game handler with an in-memory Bot API adapter; checks invitations, joining, both-message synchronization, rules, expiry, persistence, replay rejection and privacy. It does not call real Telegram or control a PC.

For official QuickJS/profile execution, clone `TelegramMessenger/widget-sandbox` and run the included `widget-sandbox-audit.ts` and `widget-sandbox-interactions.ts` from its root after exporting widgets. The scripts accept `NISLAND_WIDGET_DIR`, `NISLAND_TEST_OUTPUT` and write JSON evidence; tested with sandbox commit `7a2ec35e3e7698377626e982e98e5a1161b1aac8`.

## Required before stable — NOT yet verified

1. Run on Windows 10/11: UI, media controls including two SMTC sources/rate/seek, no startup errors, all three interface languages. Run the existing `--tg-bot-test` self-test in an isolated data directory (see its source/options), not on personal data. Existing Windows-only bot tests were updated but not executed here.
2. Use two **real** Telegram accounts and a dedicated test bot: create each game, follow an invitation, join, make turns, test expired/full link, reconnect/restart, disabled server, and confirm a third user cannot read/move/control the PC. Check current clients' widget rendering, touch activation, background throttling and captions. Sandbox tests are not a substitute.
3. Windows release build with `build.ps1` for x64, x86 and x64-lite, including the pinned Equalizer APO resource/license notices. Smoke-test all binaries.
4. Test updating an installed v2.4.4 to the candidate on Windows (download, SHA256, extraction, restart, preservation of settings/data), including wrong/missing hashes and interrupted download. No updater self-replacement was performed here.

## Existing stable release contract (unchanged)

Updater reads `https://api.github.com/repos/Neizvestnyi22/N-Island/releases/latest`.
A stable numeric tag such as `v2.5.0` (only after the above checks), non-draft/non-prerelease, must contain:

* `NIsland-2.5.0-win-x64.zip`
* `NIsland-2.5.0-win-x86.zip`
* `NIsland-2.5.0-win-x64-lite.exe`
* `SHA256SUMS.txt` generated over the exact downloadable bytes by `build.ps1`.

Updater chooses `-win-x64.zip`, `-win-x86.zip` or `-win-x64-lite.exe` suffix and verifies SHA256 before replacement. Source-only commits or prereleases do not become an update for stable clients. There is no separate manifest and no existing GitHub Actions workflow. Do not mark this source preview stable or replace v2.4.4 assets to bypass verification.
