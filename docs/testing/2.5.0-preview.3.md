# N-Island 2.5.0-preview.3 — исправление повторного открытия приглашения

Ручная тестовая сборка, не обычный GitHub-релиз. Latest v2.4.4 не меняется.
Предыдущий ZIP preview.2 это исправление **не содержит**.

## P2: повторное открытие приглашения

При повторном `/start game_<id>` участнику обновляется прежний виджет через `editMessageWidgetData`, его message ID сохраняется. «Message is not modified» считается успешным повторным открытием. Это работает и после перезапуска, ID берётся из сохранённой комнаты.

Новый виджет создаётся только если ID ещё не было или Telegram ответил HTTP 400 с `message to edit not found`. Сетевой сбой, 403/503 и невозможность редактирования не доказывают удаление сообщения: при них новое окно не создаётся, старый ID остаётся разрешённым. Неизвестные/чужие сообщения по-прежнему не получают право делать ход.

Также включён прежний финальный patch preview.2: восстановление завершённой шахматной партии и полный текст лицензии Ardalis.SmartEnum.

## Проверка на Windows двумя аккаунтами

Взять новый ZIP preview.3, новую отдельную папку и запускать TEST-PREVIEW.cmd. Нужен .NET 8 Desktop Runtime x64. Не перезаписывать рабочую 2.4.4; один токен — один процесс.

1. Создать игру, пригласить второго игрока. Запомнить оба виджета.
2. Оба игрока по очереди ещё раз открывают ту же ссылку, с интервалом хотя бы 2 секунды между запросами (защита от частых запросов).
3. Новый игровой виджет не появляется. Исходное поле продолжает отвечать и синхронизировать ходы.
4. Закрыть N-Island через «Выход», снова запустить тем же CMD. Повторить открытие приглашения и ход со старого поля.
5. Один игрок удаляет **свой тестовый игровой виджет** в Telegram, затем снова открывает приглашение. Должно появиться ровно одно новое поле, у второго игрока поле не меняется.
6. Если Telegram/сеть возвращает временную ошибку, новое поле не должно создаваться; после восстановления сети исходное поле должно работать.

Остальные проверки и ограничения наследуются из docs/testing/2.5.0-preview.2.md. Реальные Windows/WPF, Telegram, updater-миграция и нагрузка всё ещё требуют фактических результатов пользователя. Автономный тест обработчика с подменённым Bot API не заменяет их. Полные турнирные ничьи шахмат по-прежнему не реализованы.
