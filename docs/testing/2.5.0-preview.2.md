# N-Island 2.5.0-preview.2 — состояние проверки

Это исходники и тестовая сборка, **не stable**. Stable/latest остаётся v2.4.4.

## Изменения

- Повторный ответ на одну команду/кнопку заменяет прежний после успешной отправки; составные ответы индексируются, индекс сохраняется после перезапуска. Удаляются только известные исходящие ID бота, не пользовательские сообщения. Ограничение Telegram: менее 48 часов; в коде запас 47 часов. Старые ответы, отправленные до появления индекса, автоматически не обнаруживаются.
- 29 игр по приглашению (было 11): 15 новых настольных/математических игр, шахматы preview, Восьмёрки и Двадцать одно без денег. Все игровые поля отправляются как виджеты. Меню постраничное. Игроки не получают команды управления ПК. ПК должен быть включён, один токен — один процесс long polling.
- Повторное создание ещё не занятого приглашения той же игры использует прежнюю комнату. Сдача с повторным нажатием. Проверяются участник, очередь, версия состояния и ID сообщения.
- Громкость перечитывается с устройства сразу после изменения, быстрые шаги не рассчитываются от старого уровня. Событийная синхронизация панелей последовательна; фоновая синхронизация не пересоздаёт удалённые сообщения.
- Rich-меню: заголовки разделов, списки по смыслу, таблицы; обычный HTML остаётся запасным вариантом. Нет обещания, что любой старый клиент поддерживает Rich.
- Персонаж: защита повторных запросов, имя/цвет обновляются при ответе; скрытый виджет не перерисовывается, reduced motion учитывается. Размер сжатого шаблона проверяется.
- О программе → Копии и процессы: только явный запуск ограниченного сканирования. Пути, версии, PID и время запуска; совпадение имени само по себе не разрешает действия. Метаданные не являются криптографической аутентификацией издателя.

## Шахматы: честные ограничения

Gera.Chess 1.2.0 используется для легальности ходов, рокировки, взятия на проходе, выбора превращения, шаха/мата/пата. FEN и история ключей позиций сохраняются. В приложении нет часов и рейтинга.

В этой preview ничья завершается автоматически при троекратном повторе или 100 полуходах без движения пешки/взятия. Это распространённое online-правило, **не полная процедура FIDE с заявлением ничьей и отдельными обязательными 5 повторениями/75 ходами**. Базовый недостаточный материал определяется консервативно; произвольные редкие мёртвые позиции не распознаются. Соглашение о ничьей и сдача доступны. Поэтому нельзя называть реализацию полной турнирной поддержкой всех правил.

## Безопасность очистки

- Нет автоматических удалений или остановок. Для выбранного процесса — только CloseMainWindow после повторной проверки PID, времени запуска и EXE; не Kill и не дерево процессов. Приложение без обычного окна может не закрыться: это запрос, а не обещание остановки.
- Для конкретного EXE — корзина после подтверждения и проверки хеша/размера/времени изменения/запущенных процессов. Текущий EXE защищён.
- Дополнительные файлы приложения перечисляются только при полном совпадении хеша с одноимённым файлом текущего дистрибутива. Сначала удаляются выбранные дополнительные файлы, EXE последним. Смешанные/старые версии файлов остаются неизвестными и не удаляются.
- Общий %APPDATA%\NIsland и текущая папка данных защищены. data-preview — отдельная область. Её известные имена предлагаются для выбора только с маркером нового TEST-PREVIEW.cmd. Старая preview.1 маркера не имела: папка показывается, автоматическое право удалять её не возникает.
- Неизвестные файлы, системные журналы, данные других приложений и резервные копии не затрагиваются. Не гарантируется удаление «без следов» на SSD, в резервных копиях и синхронизациях.
- Поиск не полный по диску: известные папки, глубина 3, максимум 3000 каталогов, время обхода 5 секунд, максимум 100 кандидатов. Ошибки и ограничение показываются. Переименованные процессы вне выбранных путей могут не обнаружиться.

## Выполненные проверки

Linux .NET SDK 8.0.427, cross-build для Windows, сборка Release — 0 ошибок/предупреждений. Это НЕ запуск Windows/WPF.

- WidgetAudit: 1052 проверки, 16 утилит, 13 прежних шаблонов. Худший персонаж: 4056 байт zlib, лимит 4096.
- GameAudit: все 28 нешахматных игр доведены до результата; число утверждений зависит от случайной партии. Финальный прогон до упаковки: 4529. Ходы/обновления проверяются реальным обработчиком с подменённым Bot API, не сетью Telegram.
- Шахматные контрольные деревья: стартовая позиция depth 3 = 8902; Kiwipete depth 3 = 97862. Проверены рокировка, запрет через шах, en passant, Q/R/B/N, мат, пат, повтор, 50 ходов, соглашение о ничьей. Шахматная партия не проверялась двумя реальными Telegram-аккаунтами.
- ReplyAudit: 21 проверка (включая реальную обёртку, перезапуск, составные ответы, неудачу и конкуренцию); InventoryAudit: 22; AudioAudit: 10 сценариев реальных методов на подменённом COM, не на аудиоустройстве.
- Официальная песочница: 172 запуска шаблонов без диагностик/JS-ошибок; 72 сценария взаимодействия без ошибок; 6 шахматных состояний ru/en/uk × светлая/тёмная тема. Не native trusted touch и не замер геометрии реального клиента.
- PerformanceAudit (Linux тест, НЕ полная Windows-программа): 1000 create/join/move/view = 200 мс wall / 100 мс CPU; 50 новых шахматных legal views = 211 мс wall / 110 мс CPU. После них за 500 мс простоя = 0 мс CPU. Пик процесса включая .NET = 63 МиБ, managed heap = 13 МиБ. У новых игр и инвентаризации нет polling-циклов. Нагрузка на реальном ноутбуке не измерялась.

## Блокеры обычного релиза / updater

Обязательны: запуск итогового EXE на Windows 10/11 (x64/x86 и lite); реальные Telegram-виджеты, два игрока и смена языка; чтение/копия данных 2.4.4 и возврат; обновление из 2.4.4 с проверкой SHA256, замена процесса и перезапуск; CPU/RAM/I/O в простое/при игре/сканировании на Windows.

Ничего из этого не следует из успешной cross-сборки. До проверки нельзя безопасно менять latest.

Updater 2.4.4 читает `/releases/latest`, выбирает `-win-x64.zip`, `-win-x86.zip` или `-win-x64-lite.exe` и SHA256SUMS.txt. Prerelease не увидит. Version.TryParse не принимает `2.5.0-preview.2`. Следовательно, prerelease не решает запрос «скачать из установленной 2.4.4». Для этой проверки нужен ручной ZIP; обычный 2.5.0 должен публиковаться отдельно после smoke-тестов, без подмены v2.4.4.

## Удаление старой тестовой 2.5.0-preview.1

Это portable ZIP, не установщик. Его TEST-PREVIEW.cmd задавал `NISLAND_DATA=%~dp0data-preview`; EXE без cmd использовал `%APPDATA%\NIsland`.

1. Выйти из выбранной тестовой копии через меню «Выход»; убедиться, что её PID/путь исчез.
2. Удалить именно распакованную папку preview.1 (путь выбирал пользователь, универсального пути нет). В ней: NIsland.exe, README-RU.txt, TEST-PREVIEW.cmd, LICENSE.txt, THIRD-PARTY-NOTICES.txt и, если запускали cmd, data-preview. Сначала проверить личные файлы, которые пользователь мог туда добавить.
3. data-preview содержит тестовые настройки и партии; это необратимая потеря при окончательном удалении, сначала можно перенести папку в корзину.
4. Если запускали EXE напрямую, общие `%APPDATA%\NIsland` не удалять: они могут принадлежать рабочей 2.4.4. При необходимости отдельно сделать резервную копию и выбрать, какие данные стереть. Удаление тестового ZIP из Загрузок — отдельное действие.
5. Ярлык/автозапуск удалять только если он точно ссылается на выбранную копию. ОС, антивирус, резервные копии и корзина могут сохранять следы.
