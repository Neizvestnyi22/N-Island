# N-Island 2.5.0-preview.4 — m78

Тестовая LITE portable x64. Нужен .NET 8 Desktop Runtime x64. Это не обычный релиз: latest 2.4.4 и штатное обновление не меняются. Preview.3 остаётся отдельной ранее выданной сборкой с исправлением P2.

## Изменения

- В итогах **всех 29 игр**, включая шахматы/карты, указаны конкретные победитель и проигравший. Имена берутся только от самих Telegram-участников при создании/входе, ограничиваются 32 UTF-8 байтами, управляющие символы убираются, отображаются как текст. В старой партии без имени выводится конкретный ID; повторное открытие приглашения обновит имя. Имя не является проверенной личностью. Переводы ru/en/uk.
- Эквалайзер: плоская/понижающая кривая в режиме полного запаса больше не получает лишние −0,5 дБ. В настройках появился **«Убрать ослабление»** — только по явному включению с предупреждением. Он убирает автоматическое снижение предусилителя; ручное усиление сохраняется. Не включается сам, системная громкость не повышается автоматически. Для поднятых полос невозможно одновременно гарантировать прежнюю громкость и отсутствие клиппинга без измерений/лимитера; лимитер не добавлялся. Стандартный режим половинного запаса сохранён для совместимости.
- Игры/основные управляющие виджеты: ожидание запроса ограничено 8 секундами, после ошибки кнопки доступны снова; запоздалый ответ не применяется, игровой state не откатывается к меньшей версии. Двойной ход не отправляется автоматически повторно. Во время ожидания игровое поле визуально приглушается. Тяжёлый виджет персонажа не получил дополнительную обёртку из-за лимита 4096 сжатых байт — его прежняя защита от повторных тапов сохранена.
- Бот: отдельный контроль завершившейся задачи long polling; сбой первичной инициализации не убивает приём обновлений; offset удерживается локально между пакетами, не зависит от задержанного UI-сохранения. Идемпотентные getMe/getUpdates/editMessageWidgetData могут один раз повториться при сетевом/5xx сбое; отправки сообщений, файлов и команды не повторяются автоматически. Задержка переподключения ограничена 30 секундами; для 429 соблюдается retry_after (до часа), при 401/409 — 60 сек. Ошибочный токен/другая копия бота требуют исправления пользователем, не «самолечения».
- Файлы с компьютера отправляются как **документы**, с исходным именем/расширением и байтами; запрет автоматического распознавания документа как медиа. Фото/видео/звук не перекодируются этим маршрутом. Папки по-прежнему ZIP. Проверяется реальное подтверждение Telegram вместо ложного «отправлен» при некорректном ответе. Нет автоматического повтора файла при неопределённом исходе: сначала проверьте чат. Оригинал не удаляется. Доступ по-прежнему только владельцу при включённом разрешении «Файлы»; игры не дают доступа к ПК.

## Безопасный тест на ноутбуке

1. Новая папка, не поверх 2.4.4 или preview.3. Закрыть прежнюю копию. Запускать **TEST-PREVIEW.cmd**, данные — в отдельной data-preview. Один токен — один процесс. Защиту Windows не отключать.
2. Два Telegram-аккаунта: закончить крестики-нолики/карту/шахматы сдачей. У обоих должны быть правильные имена победителя и проигравшего. Поменять стороны. Повторить после перезапуска и повторного открытия одной ссылки (старые виджеты работают без новых окон — P2).
3. При низкой громкости Windows сравнить эквалайзер off/on на плоской и привычной кривой. Затем в Настройки → Эквалайзер явно включить «Убрать ослабление», прочитать предупреждение. При хрипе сразу выключить режим/понизить полосы. Проверить отдельно динамики/наушники. Не увеличивать громкость ради теста и не включать +12 дБ. Сообщить кривую, ручное усиление, устройство и результат.
4. Быстро нажать игровую/управляющую кнопку. На исходном поле не должно быть двойного хода. Отключить сеть на ПК, нажать безопасное обновление ⟳: примерно через 8 сек кнопки снова доступны. Вернуть сеть, обновить поле, затем ходить. Не повторять опасную команду/отправку файла вслепую после тайм-аута.
5. После разрыва сети и возврата бот должен снова принимать безопасные запросы. При 401 проверить токен, при 409 закрыть вторую копию/убрать конфликт webhook, не запускать две программы с одним ботом.
6. Включить разрешение «Файлы» только для нужного теста. Выбрать свои несекретные PDF/DOCX/PNG/MP3/MP4/ZIP: через /files или /get отправить в чат. Должны прийти именно документы с тем же именем/расширением. Скачать в отдельную папку и сравнить SHA256 исходного и скачанного файла:
   `Get-FileHash -Algorithm SHA256 "C:\путь\файл.pdf"`
   Хэши должны совпасть. При ошибке сначала посмотреть чат, потом решать о повторе. Проверить, что гость игры не может запросить /files.
7. Повторить пункты предыдущей Windows-инструкции: очистка только выбранных тестовых копий без неизвестных/общих файлов; миграция только на **копии** данных 2.4.4, возврат; CPU/RAM в простое/при игре. Оригинальные данные не подменять. Updater пока не должен предлагать preview.4: latest остаётся 2.4.4.
8. Прислать результаты по пунктам 2–7, точную версию Windows/Telegram, runtime, устройство звука, ошибки/скриншоты без токена и личных данных. Фактических результатов ноутбука пока нет.

## Ограничения проверки

Linux cross-build, fake HTTP/COM, mock DOM/таймеры, тесты правил/JSON-бюджетов — не Windows/WPF/Telegram и не доказательство реальной стабильности сети или качества звука. Шахматы без часов и полной турнирной процедуры ничьих; прежние ограничения сохранены. Никакого обещания «без следов» при удалении на SSD/в журналах/backup.

Точный исходный patch включён в ZIP, база main `d4ce5dd773e2998ac211e6ac77c1f501660b24dc`. Применять patch к EXE не нужно. Эта версия не заменяет stable до реальных smoke-результатов.
